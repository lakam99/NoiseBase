NoiseBase 1.9.0 keeps learned live profiles with the saved DAW song, so reopening a project no longer starts learning from scratch.

- Each plug-in instance saves separate CLEAN noise-floor and sidechain ambience caches in its host state. Up to 64 timeline regions per source store statistical profiles only; no recorded audio or external cache files are written. Save the song after learning to preserve the cache. NoiseBase notifies the host when learned state changes.
- AUTO recalls known regions after reopening, seeking or looping, then continues learning new or changed material. An uncached sidechain destination still waits for a reliable quiet profile. HOLD keeps its fixed texture. LEARN clears only the selected source's cache and restarts analysis; loaded-file LEARN still scans the entire file.
- Cached sidechain playback still respects transport and reference activity. BRIDGE schedules restored profiles at their buffered source positions and keeps its existing two-second compensated delay. Cache access in playback uses try-locks and preallocated storage; serialization runs outside the audio callback.
- The VFD shows cached-region counts and presents restored CLEAN readiness immediately. Existing control identifiers, skins and generated raster artwork are preserved. Older saved procedural profiles remain readable.

Native engine and actual VST3-host tests learn two different backgrounds for each source, save host state, then restore it in fresh processes with AUTO enabled, both with and without BRIDGE. They check that the correct saved profiles are available before enough new audio has arrived to relearn them, and that stopped playback remains silent. Additional checks cover host modification notifications, malformed/oversized state rejection, instance isolation, bounded eviction, stereo changes, edited regions and manual cache clearing. Existing audio, file, transport, latency, worker cleanup, installer and UI checks also run. Verification reports are included in the packages.

A VST3 receives audio from its host; it cannot read unplayed parts of the arrangement. Cache positions use the host timeline, so moving or replacing clips can need new learning. The cache does not capture identifiable events or voices. The exact Studio Pro song/reopen workflow has not been automatically exercised by these host tests.
