NoiseBase 1.6.0 follows changing noise across stitched dialogue clips and displays update progress in the VFD.

- Loading a file automatically scans its entire duration. Local noise profiles follow different backgrounds during standalone playback and clean/removed-noise export. LEARN manually re-analyzes the complete loaded file; HOLD freezes the active floor.
- Live VST3 AUTO learning follows stable background changes during speech pauses without requiring LEARN. Without a loaded file, LEARN restarts incoming learning. Conventional VST3 processing only sees audio delivered by the DAW; future/unplayed host audio is unavailable. Loading a reference enables whole-file scanning for file export, without assuming it is aligned with host playback.
- Audio callbacks no longer wait for speech inference, including offline-flagged host processing. Speech sessions are reused across rate changes, stale results cannot trigger quiet learning, and model cleanup runs on its owning worker. Slow worker retirement and canceled file jobs are deferred safely instead of forcing thread termination or blocking plug-in removal for seconds. This can retain the module mapping until DAW exit; close the DAW before updating.
- Windows updates show a real byte-based download percentage in a segmented cyan VFD bar. Verification, extraction and payload checks show activity without inventing a percentage. Downloads stream to disk; existing digest, checksum and payload verification remain required. Mac installation remains manual from GitHub Releases.

Validation includes stitched-background detection at 44.1/48/96 kHz, a whole-file neural scan, unchanged source length and clean/removed reconstruction, manual whole-file re-analysis, 16 VST3 create/restore/editor/remove cycles, and simulated slow startup/after-learning cleanup plus canceled scans. The synthetic later-background case improved residual noise by about 9 dB against a fixed profile; this is a test fixture, not a guarantee for every recording. Installer/update policy and atomic progress reporting are tested separately. Native reports and skin previews are included in the packages.

The reported Windows Studio Pro freeze was not reproduced inside that DAW. These changes address observed blocking and lifetime hazards and pass the native stress host; they do not establish the exact cause of that incident. Procedural ambience generation, generated raster skins, transport controls and saved parameter identifiers remain compatible.
